All your data, kept forever, found in a second

Laker is a personal data lake in a single Go binary. It copies your mailboxes, files, chats and small databases into an S3 bucket in open formats, never deletes anything, and lets you search and browse all of it from one web page, including how things were on any past date.

One place for everything you don’t want to lose

Every source is copied as it is, every change is recorded, and nothing is ever overwritten. Everything outside the bucket (the search index, the local state) is derived and can be rebuilt from it.

Search mail, chats and files at once

One box searches every message, chat and document, with highlighted matches. Text inside PDF, Office, OpenDocument and HTML files is searchable too.

Every text is indexed in Italian and in English at the same time, so mixed messages work without language detection: invoice finds invoices, and accents don’t matter.

from: · subject: · ext:pdf · kind:mail · "exact phrase" · -word

Your files, as they were on any date

Every content is stored once (by its SHA-256) and every add, change, move and delete is recorded. Pick a date and the folder shows exactly what it held then; every file has its full history, and every past version can be downloaded.

laker ls laptop:Documents --at 2026-01-31 · laker get laptop:notes.md --at 2026-01-31

Mail, kept as the original .eml

Every message of every IMAP folder is stored byte for byte, with its headers and text made searchable. Read it as text or as HTML, open the attachments, or download the .eml.

The HTML version is sanitized and shown in a sandbox; remote images, which track the reader, stay blocked until you ask for them.

Telegram and WhatsApp chats

Private chats and groups, with photos and documents. Telegram makes a slow first export, then keeps in sync; WhatsApp runs as a linked device of your phone, from the history it gets at pairing onwards.

Edits and deletions become new records: a deleted message is kept and marked deleted.

Databases, with the history of every row

Postgres and MySQL/MariaDB are read in one consistent read-only snapshot and compared with the previous run: only inserts, updates and deletes are written. No updated_at column is needed, and deletions are seen.

laker views prints DuckDB views over the lake: the latest rows, the full history, and a macro for any table as it was at a given time.

Agents next to the data

laker-agent runs where the data is (your laptop, a NAS, the office LAN) and sends what it reads to laker over signed HTTPS. Connections only go out, so nothing has to reach into your networks.

The credentials of its sources stay on the agent and never reach laker. Each agent has its own Ed25519 identity and is accepted only after you approve its ID; laker checks that every agent writes only its own sources and re-hashes everything it receives.

laker-agent config discover finds mail accounts and databases · laker agents approve <id>

Ask Claude about your lake (MCP)

Add Laker as a custom connector in Claude and ask about your mail, chats and files in plain words. The tools are read-only: search, read a document or a file’s text, list a folder now or at a date, show a file’s history.

Laker is its own OAuth server: a connector gets in only after you approve it with your web token, and the Connectors page revokes it at once.

Claude → Settings → Connectors → Add custom connector → https://<host>/mcp

Append-only, in open formats

Nothing in the lake is ever deleted or overwritten, and it works with S3 Object Lock. The bucket stays readable without Laker: originals as they were, Parquet tables and JSON manifests.

laker verify checks, reading only, that nothing is missing or damaged; snapshots of the index and state live in the bucket too, so a new server is back with laker restore.

One binary, nothing else to run

Pure Go, no cgo: one static binary for laker (Linux, macOS) and one for laker-agent (Linux, macOS, Windows). No Elasticsearch, no Tika, no database server; the index is local and is rebuilt from the bucket with laker reindex.

Packages for Homebrew, Scoop, apt, deb, rpm and apk; Docker images, systemd units and a Kubernetes manifest are in the repository.

Install

Latest release: __VERSION__. laker runs on Linux and macOS; laker-agent also on Windows.

Homebrew macOS, Linux

brew install avero-it/tap/laker
brew install avero-it/tap/laker-agent

After writing the agent’s configuration, brew services start laker-agent; see the caveats brew prints.

Scoop Windows · agent only

scoop bucket add avero-it https://github.com/avero-it/scoop-bucket
scoop install laker-agent

apt Debian, Ubuntu · amd64, arm64

sudo curl -fsSL https://avero-it.github.io/laker/laker.gpg -o /usr/share/keyrings/laker.gpg
echo "deb [signed-by=/usr/share/keyrings/laker.gpg] https://avero-it.github.io/laker stable main" | sudo tee /etc/apt/sources.list.d/laker.list
sudo apt update && sudo apt install laker laker-agent

The repository is signed and updated with every release. The packages create the laker / laker-agent system users, install the systemd units and an example configuration, and start nothing.

deb, rpm, apk Linux packages

Download from the releases page, then:

sudo apt install ./laker_<version>_linux_amd64.deb
sudo dnf install ./laker_<version>_linux_amd64.rpm
sudo apk add --allow-untrusted ./laker_<version>_linux_amd64.apk

Go Go installed

go install github.com/avero-it/laker/cmd/laker@latest
go install github.com/avero-it/laker/cmd/laker-agent@latest

Binaries, Docker

Static binaries and SHA-256 sums for every platform are on the releases page. The Dockerfile builds both images, and deploy/ has docker compose, systemd units and a Kubernetes manifest.

docker build --target laker -t laker .
docker build --target laker-agent -t laker-agent .

Quick start

On one machine, run both: laker serve and a laker-agent with server: http://127.0.0.1:8090. Elsewhere, server is the https address of laker’s reverse proxy.

  1. laker: write the configuration (the bucket and the web token), check it, start it.

    laker config create
export LAKER_S3_ACCESS_KEY=… LAKER_S3_SECRET_KEY=… LAKER_WEB_TOKEN=…
laker serve --check
laker serve

  2. laker-agent: generate its configuration, let it find your mail accounts and databases, check every source.

    laker-agent config generate
laker-agent config discover
laker-agent config validate
laker-agent serve

  3. Approve the agent with the ID it prints, here or on the Agents page. Then open http://127.0.0.1:8090 and search.

    laker agents approve lkr-xxxxxxxx-xxxxxxxx-xxxxxxxx-xxxxxxxx

A source in laker-agent.yaml

adapters:
  - name: home-mail                 # the source name in the lake: unique across all agents
    enabled: true
    type: imap                      # imap | fs | postgres | mysql | telegram | whatsapp
    schedule: "@every 10m"          # 6-field cron, @every, @hourly, or manual
    params:
      host: imap.example.com
      username: me@example.com
      password: ${IMAP_PASS}        # in laker-agent.env next to the configuration (mode 0600)
